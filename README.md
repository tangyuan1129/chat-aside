# 旁白 · chat-aside

**在聊天旁边说给你听，不替你把话发出去。**

安卓端聊天决策助手：读屏看懂局面，给你两种看法——**挑一句话说**，或者**只看局面、自己写**。
默认只把文字填进输入框，按不按发送，永远是你的事。

## 它和这个方向上的其他实现不一样在哪

这个方向上已经有不少实现（多数基于同一个上游项目）。差别不在功能多少，而在**取舍**：

| | 常见做法 | 旁白 |
|---|---|---|
| **呈现方式** | 一套面板：分析结果和候选回复混在一起 | **两套，你选**。选项模式只看能说的话；参谋模式只看局面 |
| **发送权** | 上游把「绝不自动发送」写成硬约束，不可配置 | **交回给你**。默认仍是只填入；显式开启后，连点同一选项两下才发送 |
| **参谋模式成本** | 无论要不要候选，都调两次模型（判断 + 生成） | **只调判断**，省掉生成与排序，单次成本约为三分之一 |

「不替你发」是这个项目的地基，不是没做完的功能。我们只是把**那个开关的位置，从开发者手里挪到了用户手里**。

## 两种模式

### 选项模式（默认）

面板是一串能说的话，不是一份报告。

- 每条带序号圈与推荐度，按合适度排序，第一名高亮
- 判断信息压缩成一行：危险等级色块 ＋「意图 · 动作」
- **点一下** → 填进输入框，你可以改
- **连点两下** → 真的发出去（需在设置里开启）

双击发送有两道闸，都是刻意加的：

1. 发送前校验输入框内容**等于**刚写进去的文字，对不上就中止、不发送；
2. **如果你在两次点击之间改过文字，发出去的是你改后的版本**，不会被候选覆盖。

第一下点击后有 1.5 / 2.5 / 4 秒可选的待命窗口，超时或换一条选项就取消待命。
关掉开关则退化为「只填入，永不发送」。

### 参谋模式

只给判断，不生成候选回复。

- 危险等级（1–9）
- 对方真实意图 ＋ 把握度
- 说的是字面意思，还是话里有话
- 对方想要什么 / 这一步该干什么 / 该不该马上给实质
- 紧张是否已经缓解

省掉生成模型的调用和一次判断模型的排序调用，**单次分析成本约为原来的三分之一**。
想保留候选也可打开开关，但候选降级为「参考话术」：只能复制，不能一键填入——这个模式的职责是让你看懂，不是替你说。

### 切换

设置页顶部选默认模式，悬浮球菜单里随时临时切换。改完即生效，不用重启。

## 完成度

诚实说明，避免误装。

**已完成**

- 从上游 1.3 分叉，实现上述两种模式与可配置的双击发送
- **接口配置支持自动检测可用模型**：填完密钥点一下「检测可用模型」，拉取该接口的模型列表让你挑，
  不用凭记忆手打模型名。检出的是一个可筛选的列表（OpenRouter 单接口就有几百个模型）。
  兼容 OpenAI 的对象数组、裸字符串数组、Ollama 三种返回形状；检测失败不阻断配置，模型框始终可手填
- Kotlin 包名、applicationId、应用名、主题全部改为本项目自有
- `./gradlew assembleDebug` 通过，产出 27MB debug 包（`arm64-v8a`）
- **57 条单元测试全部通过**，专门覆盖三处容易出错又不容易被发现的地方：
  - **哪个节点可以被当作发送按钮**（25 条，其中 8 条用真机实测坐标）：`发送给朋友` 这类分享面板标签必须被拒绝、转账红包收款等支付界面必须被拒绝、与输入框不同行的「发送」必须被拒绝、位于输入框左侧的节点必须被拒绝、退化尺寸的节点必须被拒绝；被键盘顶到屏幕中线以上的真实发送按钮必须仍然可用
  - **双击何时真的发送**（14 条）：关闭开关后永不发送、待命窗口超时后不发送、点了另一条选项不误发、发送之后手势重置、开关中途关闭会丢掉待命状态
  - **模型列表地址怎么推导、响应怎么解析**（18 条）：`/v1`、`/api/v1`、`/compatible-mode/v1` 以及带端点的 `/v1/systemone` 等形状都要拼对；厂商只返回空数组或结构意外时不能抛异常；地址漏了 `http://` 要给出明确提示而不是拼出畸形 URL

**已实测（真机）**

- 在 **realme GT Neo6（Android 16 / SDK 36，arm64-v8a）** 上 `adb install` 成功、启动无崩溃、首页渲染正确
- 无障碍服务与悬浮窗权限在该机上均已成功授予
- **微信真实会话里核对过发送按钮的识别**：微信的节点树完全可读（聊天名、消息内容、时间都拿得到）；
  用 uiautomator 抓到输入框 `(151,1562,917,1700)` 与发送按钮 `(1074,1562,1232,1701)` 的真实坐标后，
  发现并修正了判定规则的一处缺陷（见下）

**由这次实测修正的问题**

发送按钮的判定原先要求「位于屏幕下半部」。真机数据显示：**键盘弹起后微信把输入区压进屏幕上方
约 1700px**，发送按钮落在屏幕高度的 59% 处，只以 241px 的余量通过该检查。键盘再高一点、屏幕再矮一点，
这个检查就会把**真正的发送按钮拒掉**——而且是静默失效，用户只会觉得「点了没反应」。

现在改为：**与输入框同一行**（容差一行高度），并要求位于输入框右侧；只有完全找不到输入框时，
才退回「屏幕下半部」这个兜底启发式。「和输入框同一行」本来就更接近发送按钮的定义。

**未验证** ⚠️

- **悬浮窗渲染、选项盘的实际观感、双击手势的手感**——这几项仍未实测。
  发送按钮「找不找得到」已用真机坐标核对，但「连点两下是否真的发出去」还没有在真机上按过
- 未适配新平台；采集适配器仍是上游的微信 / QQ / X / 飞书四个
- 未做发布签名，未做首次启动引导的打磨
- 上游的题目校准、中文潜台词判断质量等问题，本项目**原样继承，未改善**

## 构建

需要 JDK 17 与 Android SDK Platform 35 / Build-Tools 35。

```bash
git clone https://github.com/tangyuan1129/chat-aside.git
cd chat-aside
./gradlew assembleDebug     # 产物：app/build/outputs/apk/debug/app-debug.apk
```

SDK 路径写在 `local.properties`（已被 gitignore）。Release 构建需要仓库外的签名配置，路径由环境变量 `JEV_KEYSTORE_PROPS` 指定——这个变量名是上游遗留的，尚未改名。

## 数据与权限

- **不需要 root，不装 Xposed，不修改聊天软件的安装包，不读其数据库。** 只用系统无障碍服务读「屏幕上正在显示的对话」，和读屏软件走同一条通道。
- 聊天内容只在你**触发分析的那一刻**发给你自己配置的模型接口。本项目没有自建服务器。
- API 密钥存在应用私有空间，不进日志、不进 git。
- 聊天历史记录默认关闭，开启后也只存在应用私有目录，可一键清空。
- 本地 OCR 使用随包的 ML Kit 中文离线模型，图片不外传。

**注意**：微信对普通无障碍服务隐藏节点，本项目沿用上游手段，把服务类名伪装为系统自带的「随选朗读」服务来读取。这是整套方案里最脆弱的一环，**微信版本更新即可能失效**。你可能认为这违反聊天软件的用户协议——请自行判断，本项目只处理你自己设备上、你自己有权查看的内容。

## 已知限制

- **国产 ROM 后台冻结**：小米 / HyperOS 会杀后台，前台保活、自启动、省电无限制都配齐仍可能失效
- **群聊**：按一对一分析，「对方」在群里会错位
- **飞书正文靠 OCR**：正文是自绘控件，可能认错字、判反说话人
- **OCR 只认屏幕上看得见的部分**：长消息被截断的部分读不到；受保护窗口截不到
- **中文判断质量**：判断模型的主训练语言是英文，题目用英文、聊天内容保留中文，建议用自己的真实对话做校准
- **只打包了 `arm64-v8a`**
- 上游的公开 issue 中还包括微信悬浮窗消失、部分机型兼容、内置渠道密钥失效等，本项目未单独处理
