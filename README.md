# 旁白 · chat-aside

**在聊天旁边说给你听，不替你把话发出去。**

安卓端聊天决策助手：读屏看懂局面，给你两种看法——**挑一句话说**，或者**只看局面、自己写**。
默认只把文字填进输入框，按不按发送，永远是你的事。

## 它和这个方向上的其他实现不一样在哪

这个方向上已经有不少实现（多数基于同一个上游项目）。差别不在功能多少，而在**取舍**：

| | 常见做法 | 旁白 |
|---|---|---|
| **呈现方式** | 一套面板：分析结果和候选回复混在一起 | **两套，你选**。选项模式只看能说的话；参谋模式只看局面 |
| **发送权** | 上游把「绝不自动发送」写成硬约束，不可配置 | **交回给你**。默认仍是只填入；显式开启后，连点同一选项两下才发送 |
| **参谋模式成本** | 无论要不要候选，都调两次模型（判断 + 生成） | **只调判断**，省掉生成与排序，单次成本约为三分之一 |

「不替你发」是这个项目的地基，不是没做完的功能。我们只是把**那个开关的位置，从开发者手里挪到了用户手里**。

## 两种模式

### 选项模式（默认）

面板是一串能说的话，不是一份报告。

- 每条带序号圈与推荐度，按合适度排序，第一名高亮
- 判断信息压缩成一行：危险等级色块 ＋「意图 · 动作」
- **点一下** → 填进输入框，你可以改
- **连点两下** → 真的发出去（需在设置里开启）

双击发送有两道闸，都是刻意加的：

1. 发送前校验输入框内容**等于**刚写进去的文字，对不上就中止、不发送；
2. **如果你在两次点击之间改过文字，发出去的是你改后的版本**，不会被候选覆盖。

第一下点击后有 1.5 / 2.5 / 4 秒可选的待命窗口，超时或换一条选项就取消待命。
关掉开关则退化为「只填入，永不发送」。

### 参谋模式

只给判断，不生成候选回复。

- 危险等级（1–9）
- 对方真实意图 ＋ 把握度
- 说的是字面意思，还是话里有话
- 对方想要什么 / 这一步该干什么 / 该不该马上给实质
- 紧张是否已经缓解

省掉生成模型的调用和一次判断模型的排序调用，**单次分析成本约为原来的三分之一**。
想保留候选也可打开开关，但候选降级为「参考话术」：只能复制，不能一键填入——这个模式的职责是让你看懂，不是替你说。

### 切换

设置页顶部选默认模式，悬浮球菜单里随时临时切换。改完即生效，不用重启。

## 跨机型：能装在别的手机上吗

能，但**必须正视一个系统级事实**：国产 ROM 会积极清理后台，而安卓在 App 被强杀后，
会把它的无障碍服务**当成崩溃并自动从启用列表移除**。这在真机日志里看得很清楚：

```
ActivityManager: Force stopping … : o-stop(40)
AccessibilityUserState: [serviceDisconnectedLocked] add mCrashedServices …
AccessibilityManagerService: mEnabledServices = [无障碍菜单, …]   ← 我们的服务被移出
```

结果就是：**App 从这一刻起什么都不做，而界面上没有任何东西说明原因。** 用户只会觉得「用不了了」。

程序化重新开启无障碍是安卓明令禁止的，所以这里能做的只有三件事：

| 做法 | 说明 |
|---|---|
| **让失效可见** | 后台每 5 秒自查一次无障碍是否还在。一被关掉，5 秒内弹出**可点击的通知**——「无障碍已被系统关闭」——点它直达系统设置页；你重新打开后通知自动消失 |
| **让它自己能启动** | 看门狗既由应用首页启动，也在开机后自动启动（BOOT_COMPLETED）。第一版只让它由无障碍服务启动——那是个引导缺陷：恰恰在「无障碍被关掉」这个唯一有意义的场景下，它自己根本起不来 |
| **提供跨品牌通用的入口** | 各家的「自启动」界面**没有公开接口，代码打不开**；但**电池优化白名单**是 Android 6+ 通用的标准 API。首页权限卡里单独列了一行 |
| **按机型给真实路径** | 小米/Redmi/POCO/黑鲨、OPPO/一加/realme、华为/荣耀、vivo/iQOO、三星、魅族、努比亚/红魔/中兴、华硕/ROG、联想/摩托罗拉、Tecno/Infinix/itel，以及接近原生安卓的机型 |

最后一条尤其重要：上游原文写的是「小米/HyperOS 必做」，因为那是作者的机型。
**在别的手机上说这句话，等于把人指向一个不存在的界面**——比不说还糟。

### 看门狗的局限，必须说清楚

**看门狗跑在本应用自己的进程里，所以它会被和解决不了的那个问题一起被杀掉。**

在实测机型上（realme / ColorOS），App 未加入白名单时只能存活十几秒，系统一杀，看门狗跟着没。
因此它的作用是：**你放开「自启动 + 省电」之后再出问题，它会立刻告诉你并带你去修**；
而不是「装上就能免疫系统清理」。

换句话说，这里的正确顺序是：

1. 先按屏幕上的机型路径**放开自启动和省电**（这一步只能人来做，代码打不开那些界面）
2. 之后再被系统清掉时，**看门狗负责把这件事变得可见**

> **真机验证（2026-09-23，realme / ColorOS / Android 16）**：
> 上述全链路已实测通过——授予通知权限后，无障碍处于关闭状态时打开 App，
> 告警「无障碍已被系统关闭，旁白已失效」正常弹出，常驻通知「旁白正在运行」同屏可见。
> 两个此前拦住它的 bug（看门狗引导死锁、POST_NOTIFICATIONS 从未在运行时申请）均已修复并有提交记录。

把「加了看门狗」说成「解决了被杀的问题」是不诚实的——它解决的是**被杀之后用户毫不知情**这个问题。

**已实测（真机）**

- 在 **realme GT Neo6（Android 16 / SDK 36，arm64-v8a）** 上 `adb install` 成功、启动无崩溃、首页渲染正确
- 无障碍服务与悬浮窗权限在该机上均已成功授予
- **微信真实会话里核对过发送按钮的识别**：微信的节点树完全可读（聊天名、消息内容、时间都拿得到）；
  用 uiautomator 抓到输入框 `(151,1562,917,1700)` 与发送按钮 `(1074,1562,1232,1701)` 的真实坐标后，
  发现并修正了判定规则的一处缺陷（见下）
- **判断面板在真实微信会话里跑通了**：悬浮球与面板正常渲染在聊天上方，实战输出形如
  `危险 3/9 留神` / `对方真实意图：确认你在不在乎（把握 50%）` / `话里有话：…` / 参考话术两条。
  判断接口用 DeepSeek 经「聊天模型兼任判断」通道，871ms 返回，结果正确
- **定位到「用着用着就没反应了」的真正原因**：系统强杀 App → 无障碍被安卓判定为崩溃并自动移除
  （完整日志见 [跨机型](#跨机型能装在别的手机上吗)）。这不是配置错误，因此本轮加了看门狗把它变成可见的
- **权限与看门狗链路在该机全绿复查（2026-09-24）**：无障碍 / 通知 / 悬浮窗 / 省电优化白名单四项均已开启，
  `adb install -r` 覆盖安装后无障碍设置保留、进程存活、告警通知可弹出
- **抖音适配器按真实节点树重写（2026-09-24）**：在真机抖音私信会话里 `uiautomator dump` 抓到
  完整节点树，确认两个稳定特征——私信输入框 `msg_et` 是全屏唯一未混淆的资源 ID（评论框没有），
  真实气泡文本不带 resource-id 而联系人横滑条 / 快捷回复 / 时间戳 / 系统公告全带——
  旧几何规则会把这些杂物当成消息（联系人条一行就有 5 条，正好喂饱「≥4 行」误判兜底）。
  新逻辑：有 `msg_et` 走精确路径（只取消息列表内的无 ID 文本），否则退回几何兜底并禁用该误判形状

**由这次实测修正的问题**

发送按钮的判定原先要求「位于屏幕下半部」。真机数据显示：**键盘弹起后微信把输入区压进屏幕上方
约 1700px**，发送按钮落在屏幕高度的 59% 处，只以 241px 的余量通过该检查。键盘再高一点、屏幕再矮一点，
这个检查就会把**真正的发送按钮拒掉**——而且是静默失效，用户只会觉得「点了没反应」。

现在改为：**与输入框同一行**（容差一行高度），并要求位于输入框右侧；只有完全找不到输入框时，
才退回「屏幕下半部」这个兜底启发式。「和输入框同一行」本来就更接近发送按钮的定义。

**未验证** ⚠️

  （评论列表单列应无法满足误判条件，但没有真机 dump 佐证）
- **飞书的已读状态判定（feishuHasReadState）未真机验证**，说话人分边依赖它
- 采集适配器现共六个：微信 / QQ / X / 飞书 / 抖音 / 抖音lite；其中抖音、抖音lite 为本项目新增

## 构建

需要 JDK 17 与 Android SDK Platform 35 / Build-Tools 35。

```bash
git clone https://github.com/tangyuan1129/chat-aside.git
cd chat-aside
./gradlew assembleDebug     # 产物：app/build/outputs/apk/debug/app-debug.apk
```

SDK 路径写在 `local.properties`（已被 gitignore）。Release 构建需要仓库外的签名配置，路径由环境变量 `JEV_KEYSTORE_PROPS` 指定——这个变量名是上游遗留的，尚未改名。

## 数据与权限

- **不需要 root，不装 Xposed，不修改聊天软件的安装包，不读其数据库。** 只用系统无障碍服务读「屏幕上正在显示的对话」，和读屏软件走同一条通道。
- 聊天内容只在你**触发分析的那一刻**发给你自己配置的模型接口。本项目没有自建服务器。
- API 密钥存在应用私有空间，不进日志、不进 git。
- 聊天历史记录默认关闭，开启后也只存在应用私有目录，可一键清空。
- 本地 OCR 使用随包的 ML Kit 中文离线模型，图片不外传。

**注意**：微信对普通无障碍服务隐藏节点，本项目沿用上游手段，把服务类名伪装为系统自带的「随选朗读」服务来读取。这是整套方案里最脆弱的一环，**微信版本更新即可能失效**。你可能认为这违反聊天软件的用户协议——请自行判断，本项目只处理你自己设备上、你自己有权查看的内容。

## 已知限制

- **国产 ROM 后台冻结**：小米 / HyperOS 会杀后台，前台保活、自启动、省电无限制都配齐仍可能失效
- **群聊**：按一对一分析，「对方」在群里会错位
- **飞书正文靠 OCR**：正文是自绘控件，可能认错字、判反说话人
- **OCR 只认屏幕上看得见的部分**：长消息被截断的部分读不到；受保护窗口截不到
- **中文判断质量**：判断模型的主训练语言是英文，题目用英文、聊天内容保留中文，建议用自己的真实对话做校准
- **只打包了 `arm64-v8a`**
- 上游的公开 issue 中还包括微信悬浮窗消失、部分机型兼容、内置渠道密钥失效等，本项目未单独处理
